# 大富翁（Rich）命令行版

这是一个使用 C11 编写的 70 格命令行大富翁游戏。项目按地图、回合、命令、房产、道具、礼品屋和魔法屋等模块组织，并提供覆盖 A1～A20 相关功能的自动测试。

## 当前规则口径

程序优先遵循《大富翁》PDF 说明，并按项目约定处理以下冲突：

1. 礼品屋中输入 `Help` 后保留当前礼品选择。
2. 固定位置为：`T=28`、`G=35`、`P=49`、`M=63`、矿地 `64～69`。
3. 遇到路障时停在路障所在格，并处理该格事件。
4. 入狱后轮空两次。
5. `Quit` 结束整局游戏。

其他已实现规则包括：炸弹送入医院并轮空三次；普通到达医院不产生额外效果；玩家破产后房产和道具归还系统；仅剩一名未破产玩家时游戏结束。

## 编译

建议在 Visual Studio Developer PowerShell 或已经配置好 CMake、Ninja 和 C 编译器的 PowerShell 中执行：

```powershell
cd D:\test\rich
cmake -S . -B build-ninja -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build-ninja
```

生成的主要程序：

- `build-ninja/rich.exe`：当前正式运行程序。
- `build-ninja/monopoly.exe`：兼容名称，功能与 `rich.exe` 相同。

## 运行

```powershell
cd D:\test\rich\build-ninja
.\rich.exe
```

### 开局输入

开局顺序为“初始资金 → 一次性选择角色”。

1. 输入 `1000～50000` 范围内的初始资金；第一次直接按回车使用默认值 `10000`。
2. 输入合法资金后立即进入角色选择，不需要再次确认。
3. 一次性输入 2～4 个不重复的角色编号，编号顺序就是玩家顺序。

角色编号与地图字符：

| 编号 | 地图字符 | 玩家颜色 |
| --- | --- | --- |
| 1 | Q | 红色 |
| 2 | A | 绿色 |
| 3 | S | 蓝色 |
| 4 | J | 黄色 |

例如：

- 输入 `12`：一号玩家为角色 1（Q），二号玩家为角色 2（A）。
- 输入 `324`：一号玩家为角色 3（S），二号玩家为角色 2（A），三号玩家为角色 4（J）。

## 游戏命令

命令不区分大小写。

| 命令 | 说明 |
| --- | --- |
| `Roll` | 掷骰子并移动，进入下一名玩家的回合 |
| `Step n` | 测试/调试用，向前移动 `n` 格并处理沿途事件 |
| `Sell n` | 出售地图绝对位置 `n` 上属于当前玩家的房产 |
| `Block n` | 在前方或后方 `n` 格放置路障，范围为 `-10～10` |
| `Bomb n` | 在前方或后方 `n` 格放置炸弹，范围为 `-10～10` |
| `Robot` | 使用机器娃娃清除前方 10 格内的路障和炸弹 |
| `Query` | 查询当前玩家的资金、点数、道具和状态 |
| `Map` | 重新显示地图和逐格明细 |
| `Help` | 显示帮助信息 |
| `Quit` | 结束整局游戏 |

特殊场景中的选择按屏幕提示输入；通常可输入 `F` 退出当前选择。

## 地图

地图共 70 格，按顺时针方向编号为 `0～69`。关键位置如下：

| 位置 | 符号 | 类型 |
| ---: | :---: | --- |
| 0 | S | 起点 |
| 14 | H | 医院 |
| 28 | T | 道具屋 |
| 35 | G | 礼品屋 |
| 49 | P | 监狱 |
| 63 | M | 魔法屋 |
| 64～69 | `$` | 矿地 |

空地价格按地图区段计算，矿地会按位置给予点数奖励。

### 地图与逐格明细

地图上的玩家字符和逐格明细中的玩家后缀都使用对应角色颜色。逐格明细格式为：

```text
[编号:当前格子符号/所在玩家]
```

示例：

- `[11:0]`：11 号格为空地，当前没有玩家停留。
- `[11:0/Q]`：Q 玩家当前停在 11 号空地。
- `[14:H/A]`：A 玩家当前停在医院。

房产所有者不再显示为 `/Q`、`/A` 等后缀。房产归属只通过房产等级字符 `0/1/2/3` 的颜色表示；斜杠后的角色只表示当前停在该格的玩家。

## 房产规则

- 玩家停在未购买的空地时可以选择购买。
- 玩家停在自己的空地或房屋时可以选择升级。
- 房屋分为三级，地图字符依次为 `0`、`1`、`2`、`3`。
- 每次购买或升级的费用等于该地块的空地价格。
- 停在其他玩家的房产上，需要支付房产当前价值一半的过路费。
- 财神附身期间可免交过路费；房主在医院或监狱时也免收过路费。
- 同一轮内连续发生破产时，后一笔破产结算会补齐上一笔未付足的过路费；当前一笔仍按玩家实际可支付金额入账。
- `Sell n` 的售价为该房产累计投资总成本的两倍。
- 玩家资金不足且无法继续支付时破产，其房产和道具会重置并归还系统。

## 道具、礼品屋和魔法屋

### 道具屋

| 道具 | 点数价格 |
| --- | ---: |
| 路障 | 50 |
| 机器娃娃 | 30 |
| 炸弹 | 50 |

每位玩家最多持有 10 个道具。点数不足时不能购买；可输入 `F` 离开道具屋。

### 礼品屋

| 选择 | 礼品 | 效果 |
| --- | --- | --- |
| 1 | 奖金 | 增加 2000 元 |
| 2 | 点数卡 | 增加 200 点 |
| 3 | 财神 | 获得 5 轮财神效果 |

输入无效选择会退出礼品屋；输入 `Help` 会显示帮助并保留当前礼品选择。

### 魔法屋

魔法屋保留可注册的魔法回调接口。当前内置选择支持确认、拒绝和退出流程；输入 `F` 可离开魔法屋，后续可以在不修改公共接口的前提下注册扩展魔法效果。

## 自动测试

编译完成后运行：

```powershell
ctest --test-dir build-ninja --output-on-failure
```

当前 CMake 注册了 8 组测试：

- `test_a1`：开局输入与玩家初始化。
- `test_a4`、`test_a4_runtime`：回合状态与运行时流程。
- `test_map`：70 格地图、位置与显示。
- `test_property`：A9/A10/A11 房产购买、升级、收费、出售和破产流程。
- `test_a15`：礼品屋。
- `test_a16`：魔法屋。
- `test_a20`：道具及其运行时集成。

最近一次完整测试结果为 8/8 组通过；其中房产规则测试为 71/71，房产集成测试为 20/20。

### 跨组 JSON 黑盒测试

`monopoly_test` 是独立的自动化测试入口，不改变 `rich` 的交互启动方式。它按固定契约接收：

```text
monopoly_test <test_case.json> <map.json>
```

并只向 stdout 输出 Actual 状态 JSON 或 ERROR 报告。可以直接执行 `build.bat` 生成
`monopoly_test.exe`；随后由测试侧的 `run_tests` 将 `--program` 指向该文件。

## 项目结构

```text
include/                 公共头文件（接口）
src/
  main.c                 程序入口
  commands/              命令解析与分发
  map/                   地图初始化、位置和显示
  property/              房产购买、升级、收费、出售和破产
  runtime/               游戏主循环与场景衔接
  story/                 礼品屋、魔法屋等特殊格子
  tools/                 路障、炸弹、机器娃娃
  turn/                  回合和玩家状态
tests/                   自动测试
docs/                    模块接口和测试说明
CMakeLists.txt           构建与测试配置
```

公共接口位于 `include/`，具体实现位于 `src/`。更新功能时应尽量保持头文件接口稳定，并在对应的 `tests/` 中补充验证。
