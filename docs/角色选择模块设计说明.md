# 角色选择模块设计说明

## 1. 需求来源

- 《大富翁.pdf》开局流程：选择 2~4 名玩家，轮流选择不重复的角色开始游戏。
- 《大富翁游戏自动化测试JSON接口规范v1.1》§3.1 玩家表：

| 编号 | 角色   | 颜色 | 地图显示符号 |
|------|--------|------|--------------|
| 1    | 钱夫人 | 红色 | Q            |
| 2    | 阿土伯 | 绿色 | A            |
| 3    | 孙小美 | 蓝色 | S            |
| 4    | 金贝贝 | 黄色 | J            |

## 2. 模块划分

| 模块       | 文件                          | 职责 |
|------------|-------------------------------|------|
| character  | include/character.h, src/character.c | 角色静态数据表与编号校验 |
| player     | include/player.h, src/player.c       | 玩家数据结构、选择合法性校验、玩家数组创建 |
| selection  | include/selection.h, src/selection.c | 交互向导：人数输入 → 轮流选择 → 结果确认 |
| game       | include/game.h, src/game.c           | 游戏创建（确认之后）、进入第一个回合 |
| console    | include/console.h, src/console.c     | Windows 控制台 UTF-8 / ANSI 颜色初始化 |
| main       | src/main.c                            | 程序入口：串起 选择 → 确认 → 创建 → 第一回合 |

## 3. 需求逐条追踪

| 需求 | 实现位置 | 说明 |
|------|----------|------|
| 仅允许 2、3、4 名玩家 | `input_player_count()` (selection.c) | `MIN_PLAYERS=2` / `MAX_PLAYERS=4` |
| 人数 <2 或 >4 说明合法范围并重输 | `input_player_count()` | 提示“仅支持 2~4 名玩家，请重新输入”后循环 |
| 人数输入为非法字符 | `input_player_count()` + `parse_int()` | 提示“请输入整数形式的人数”；纯数字校验，小数、正负号、文字等一律拒绝 |
| 按玩家1~N 顺序引导选择 | `selection_wizard()` 主循环 | `for i in 0..count-1`，玩家号 = i+1 |
| 输入角色编号即选择该角色 | `input_character_for_player()` | 编号 1~4 |
| 角色名/颜色/拼音缩写 | `g_characters[]` (character.c) | Q/A/S/J 符号 + ANSI 颜色输出 |
| 每人必须选一个角色 | 向导循环 | 未选出合法角色前不会进入下一名玩家 |
| 同一局角色不得重复 | `taken[]` 标记 + `player_selection_valid()` | 交互层拦截 + 创建前二次校验 |
| 已选角色不再出现在可选项 | `show_available_characters()` | 只打印 `taken[id]==0` 的角色 |
| 每次选择显示当前玩家与剩余角色 | `input_character_for_player()` | “当前操作：玩家N” + 剩余角色列表 + 已完成进度 |
| 不存在角色给原因并重选 | 编号校验分支 | “不存在编号为 X 的角色” |
| 重复角色给原因并重选 | `taken[]` 分支 | “已被 玩家M 选择” |
| 非法字符给原因并重选 | `parse_int()` 失败分支 | “请输入数字形式的角色编号”；纯数字校验，小数、正负号、文字等一律拒绝 |
| 全部完成并确认后才创建游戏 | main.c | `selection_wizard()` 返回 1 → `game_create()` |
| 失败/未确认不产生半初始化数据 | 全程仅操作栈上 `chosen[]` 意向数组 | `Player`/`Game` 只在确认后一次性完整初始化；`game_create()` 校验失败返回 NULL |
| 超长输入防护 | `read_line()` | 128 字节缓冲，超长截断丢弃 |

## 4. 关键设计：不产生半初始化玩家数据

```
输入阶段（栈上临时数据）           确认                创建阶段（堆上正式数据）
┌──────────────────────┐      ┌───────┐      ┌────────────────────────┐
│ count  int           │      │ Y →   │ ───▶ │ game_create()          │
│ chosen[MAX_PLAYERS]  │ ───▶ │       │      │  ├─ player_selection_valid() 复检
│ taken[]  标记        │      │ N →   │ ───▶ │  ├─ malloc Game         │
│ （纯“选择意向”）      │      │ 丢弃重来 │      │  └─ player_create_all() 完整初始化 │
└──────────────────────┘      └───────┘      └────────────────────────┘
```

- 选择中途（含每次非法重输、按 N 重选）只修改栈上的编号数组，**不触碰** `Player`/`Game`；
- `game_create()` 内部再次调用 `player_selection_valid()` 做防御性校验，
  任何一步失败都返回 NULL 并释放已分配内存，保证不会残留半初始化对象。

## 5. 交互示例

```
请输入玩家人数（2~4 人）：3

----------------------------------------
当前操作：玩家1
剩余可选角色：
  1. 钱夫人（红色，地图显示 Q）
  2. 阿土伯（绿色，地图显示 A）
  3. 孙小美（蓝色，地图显示 S）
  4. 金贝贝（黄色，地图显示 J）
玩家1，请输入角色编号选择角色：2
玩家1 选择了 阿土伯（绿色，地图显示 A）。

----------------------------------------
当前操作：玩家2
已完成选择：玩家1→阿土伯(A)
剩余可选角色：
  1. 钱夫人（红色，地图显示 Q）
  3. 孙小美（蓝色，地图显示 S）
  4. 金贝贝（黄色，地图显示 J）
玩家2，请输入角色编号选择角色：2
选择失败：角色「阿土伯」已被 玩家1 选择，同一局内角色不得重复，请从剩余角色中重新选择。
```
