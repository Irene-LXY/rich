# A3 默认资金修复与 A21 自动化测试设计

## 目标

- 修复开局初始资金步骤的空输入行为：玩家直接按回车时采用默认资金 10000 元，不显示“命令不能为空”。
- 为 Excel 中 `Case_A21_001` 至 `Case_A21_033` 建立可重复执行、结果可按用例编号追踪的自动化测试。
- 提供 Windows PowerShell 一键运行入口和简明使用说明。

## 根因

`command_execute()` 在识别游戏仍处于开局引导阶段之前，先对输入执行了通用空命令校验。空行因此在命令分发层被拒绝，无法到达 `startup_handle_input()` 的初始资金处理逻辑。

## 修复设计

命令分发层保留运行期“空命令无效”的现有行为，但在 `game->runtime == NULL` 且 `game->setup_step == SETUP_INITIAL_MONEY` 时，将空输入交给开局处理器。开局处理器把空输入解析为默认值 10000，并按现有流程创建运行时。

该改动只放宽初始资金步骤，不改变角色组合输入、正常游戏命令或结束后命令的空输入规则。

## 测试设计

### A3 回归测试

新增独立测试，执行完整开局调用链：

1. 启动游戏；
2. 输入合法角色组合；
3. 在初始资金步骤传入空字符串；
4. 验证命令成功、运行时创建、所有玩家资金均为 10000，且输出不包含“命令不能为空”。

测试必须在生产代码修改前运行并以预期原因失败，以证明它确实捕获当前缺陷。

### A21 自动化测试

新增 `tests/test_a21.c`，以 Excel 用例编号输出逐项通过或失败结果。测试优先使用公开的 `PropertySystem`、礼品屋和 A4 回合管理接口构造确定性场景，覆盖：

- 资金小于 0 触发破产，资金等于 0 不破产；
- 单处及多处房产释放、房屋等级和归属复位；
- 资金不足时购买或升级被拒绝；
- 出售房产及奖金增加资金时不触发破产；
- 财神、住院、入狱及组合状态下免过路费；
- 财神第五轮有效、第六轮失效的边界；
- 玩家退出、跳过破产玩家、仅剩一人时结束游戏；
- 连续两名玩家破产后的参与人数与回合顺序。

当多条 Excel 用例描述同一底层规则但参数不同，使用数据驱动表逐条执行，仍分别打印对应的 `Case_A21_NNN`，确保 33 个编号均有独立结果。

### 运行入口

在 CMake 中注册 `A21_bankruptcy` 测试，并新增 `scripts/run_a21_tests.ps1`：

- 检查 CMake 与可用构建工具；
- 配置并构建 `test_a21`；
- 仅运行 A21 测试并显示失败详情；
- 以进程退出码表示成功或失败。

## 验证标准

- A3 回归测试完成红灯到绿灯的验证。
- `Case_A21_001` 至 `Case_A21_033` 全部被执行且通过。
- 完整 CTest 套件无回归。
- 项目能从干净的构建目录成功配置和编译。
- PowerShell 脚本可从项目目录直接执行，并在失败时返回非零退出码。

## 非目标

- 不修改 Excel 文件本身。
- 不重构与 A3/A21 无关的命令、地图或剧情模块。
- 不为测试暴露可修改生产状态的公共调试接口；若现有公开模块接口足够，则不增加测试专用生产 API。
