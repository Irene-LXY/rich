# 初始资金与破产模块设计说明（A3 / A17 / A21）

本文档对应功能点：**A3 初始资金设置**、**A17 破产与土地归还**、**A21 只剩一名玩家时游戏结束**。
角色选择部分见《角色选择模块设计说明.md》。

## 1. 模块划分

| 模块      | 文件                            | 职责 |
|-----------|---------------------------------|------|
| fund      | include/fund.h, src/fund.c      | 初始资金常量、数值校验、交互设置向导（A3） |
| game      | include/game.h, src/game.c      | 地产表、初始资金原子写入、交易/收费、破产与游戏结束判定（A3/A17/A21） |
| player    | include/player.h, src/player.c  | 玩家结构新增 fund（资金）与 status（正常/破产） |
| input     | include/input.h, src/input.c    | 行读取、去空格、整数解析（selection 与 fund 共用） |
| demo      | include/demo.h, src/demo.c      | 破产机制脚本化演示（`--demo` 参数运行） |

## 2. 开局设置总流程

```
selection_wizard()          角色选择（A2，未确认不创建任何数据）
      │ 确认 Y
      ▼
game_create()               创建游戏与玩家（fund=0，地产全为空地）
      │
      ▼
fund_wizard()               初始资金设置（A3，未确认不写入任何资金）
      │ 确认 Y
      ▼
game_enter_first_round()    进入第 1 回合
```

## 3. A3 初始资金：需求逐条追踪

| 需求 | 实现位置 | 说明 |
|------|----------|------|
| 游戏开始前统一发放初始资金 | main.c 流程 | fund_wizard 在 game_create 之后、进入第 1 回合之前 |
| 范围 1000~50000，默认 10000 | fund.h 常量 + `input_initial_fund()` | 空行（或纯空格）→ 采用默认值并明示 |
| 所有玩家初始资金相同 | `game_set_initial_fund()` | 单一数值单次循环写入 + 写入后逐人复核不变式 |
| 确认前显示最终采用数值 | `confirm_initial_fund()` | “最终采用的初始资金：每名玩家 X 元”，默认值会标注 |
| 小数/文字/非法字符给原因 | `input_initial_fund()` 纯数字校验 | 提示合法格式（纯数字整数）与范围；首尾空格容忍，中间空格视为非法 |
| 超出范围给原因 | `initial_fund_valid()` | 提示“X 超出范围，合法范围 1000~50000” |
| 非法输入留在当前步骤重输 | 输入循环 | 不推进流程 |
| 确认后才写入玩家资产 | fund_wizard 主循环 | Y 之前玩家资金保持 0；`game_set_initial_fund` 只在确认后调用 |
| 错误/取消不产生部分修改 | `game_set_initial_fund()` | 校验先于写入；写入循环无任何可失败操作 → 全写或不写；N/EOF 时完全不写 |

## 4. A17 / A21 破产：需求逐条追踪

| 需求 | 实现位置 | 说明 |
|------|----------|------|
| 交易/收费使资金 < 0 时宣布破产 | `game_charge()` → `game_declare_bankruptcy()` | 全额扣款（int64 计算防溢出）→ 债权人入账 → 判定资金 < 0 |
| 资金等于 0 不破产 | `game_charge()` | 仅 `fund < 0` 触发（接口规范 §9.1 一致） |
| 土地归还系统、初始化为空地 | `game_declare_bankruptcy()` | 遍历地产表：owned=0, owner=-1, level=0 |
| 空地可供其他玩家重新购买 | `game_add_property()` | 仅空地可登记；演示中破产归还后由其他玩家成功购入 |
| 只剩一名玩家时游戏结束 | `game_declare_bankruptcy()` | `game_active_player_count()==1` → status=FINISHED 并宣布获胜者 |
| 破产玩家不再参与交易 | `game_charge()` 前置校验 | 已破产玩家付款直接拒绝 |

## 5. 破产处理时序

```
game_charge(payer, amount, creditor)
  ├─ 前置校验（游戏进行中 / 付款人未破产 / amount>0 / 债权人合法）→ 失败返回 0，零修改
  ├─ 全额扣款：payer.fund -= amount（int64 计算，防 int32 溢出）
  ├─ 债权人入账：creditor.fund += amount（系统收款则跳过）
  └─ payer.fund < 0 ?
       ├─ 否（含恰好为 0）→ 结束，玩家正常
       └─ 是 → game_declare_bankruptcy()
            ├─ payer.status = BANKRUPT
            ├─ 名下全部土地 → 空地（owned=0, owner=-1, level=0）
            └─ 未破产玩家只剩 1 人？→ GAME_STATUS_FINISHED，宣布获胜者
```

## 6. 演示验证（`bin\A3_A17_A21.exe --demo`）

| 场景 | 内容 | 验证点 |
|------|------|--------|
| 前置 | 玩家1 持有位置 6、8 两块地 | 地产登记 |
| 场景 1 | 玩家1 付租金 12000（10000→-2000） | 交易致破产；两块地归还系统；游戏继续（剩 2 人） |
| 验证 | 玩家2 购入已归还的位置 6 | 空地可重新购买 |
| 场景 2 | 玩家3 缴费 10000（10000→0） | 资金等于 0 不破产 |
| 场景 3 | 玩家2 缴费 25000（22000→-3000） | 收费致破产；土地归还；只剩 1 人 → 游戏结束，玩家3 获胜 |
